Realistic work, laddered:

1. [01-good-first-tickets.md](01-good-first-tickets.md) — 16 junior tickets (locate, small change, test)
2. [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) — 10 cross-layer tickets requiring design notes

4. [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) — judgment reps

Contribution realism rules (from the ground rules): every ticket answers *why it's useful, why the blast radius is small, which existing pattern it follows, how it's tested, and what would make a maintainer reject it.* Every ticket lists **Interview story potential** — the STAR story finishing it would mint ([worksheets here](../08-interview-prep/06-behavioral-star-stories.md)).

Workflow for every ticket: branch → read the listed anchors *first* → write the test or manual verification plan → implement → self-review with the [security](../05-quality-engineering/05-security-checklist.md) and [review](../07-career-and-collaboration/01-code-review-mindset.md) checklists → write the PR description per [the guide](../07-career-and-collaboration/02-writing-prs-and-rfcs.md).
